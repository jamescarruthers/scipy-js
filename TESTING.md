# Testing Guide for scipy-js

This document explains the testing infrastructure for scipy-js and how to use it.

## Overview

The scipy-js project uses a dual testing approach:

1. **Unit tests** - Basic JavaScript tests that validate functionality
2. **Python comparison tests** - Tests that validate JavaScript output against scipy's Python implementation

## Running Tests

### All Tests

Run the complete test suite:

```bash
npm test
```

This runs the basic unit tests in `test.js`.

### Python Comparison Tests

Run tests that compare JavaScript output with Python scipy:

```bash
npm run test:python-compare
```

Or directly:

```bash
node --test tests/test_with_python_data.js
```

## Test Structure

### Basic Tests (`test.js`)

Located in the root directory, these tests cover:
- LIL matrix creation and operations
- CSR matrix creation and operations
- Linear algebra functions (dot, norm, matmul, transpose, solve)
- Sparse eigenvalue solver (eigsh)

### Python Comparison Tests (`tests/test_with_python_data.js`)

More comprehensive tests that validate against scipy output:
- **Sparse Matrices**: Validates LIL and CSR matrix behavior matches scipy
- **Linear Algebra**: Validates all linalg operations produce identical results
- **Sparse Matrix-Vector**: Validates CSR matvec operations
- **Eigenvalues**: Validates eigsh produces similar eigenvalues (with tolerance)

These tests load expected results from `tests/test_data.json` which is generated by the Python script.

## Test Data Generation

### Prerequisites

To regenerate test data, you need Python with numpy and scipy installed:

```bash
pip install numpy scipy
```

### Generating Test Data

The test data is generated using `tests/generate_test_data.py`:

```bash
cd tests
python3 generate_test_data.py
```

**Important**: The script must be run from within the `tests` directory to avoid import conflicts with the scipy source code in the repository root.

This generates `tests/test_data.json` containing:
- Expected outputs from scipy for various operations
- Test matrices and vectors
- Expected eigenvalues and eigenvectors

### Test Data Structure

The generated JSON file has the following structure:

```json
{
  "sparse_matrices": [
    {
      "name": "test_name",
      "dense": [...],
      "lil": { "shape": [...], "nnz": N, "todense": [...] },
      "csr": { "shape": [...], "nnz": N, "data": [...], "indices": [...], "indptr": [...] }
    }
  ],
  "linalg_operations": [
    {
      "name": "test_name",
      "operation": "dot|norm|matmul|...",
      "inputs": { ... },
      "expected": ...
    }
  ],
  "sparse_matvec": [...],
  "eigsh": [...]
}
```

## Adding New Tests

### Adding a Unit Test

Edit `test.js` and add a new test case:

```javascript
test('My new feature', () => {
  // Test code here
  assert.strictEqual(result, expected);
});
```

### Adding a Python Comparison Test

1. Edit `tests/generate_test_data.py`
2. Add your test case to the appropriate generation function
3. Regenerate test data:
   ```bash
   cd tests
   python3 generate_test_data.py
   ```
4. Run tests to verify:
   ```bash
   npm run test:python-compare
   ```

Example adding a new linalg test:

```python
def generate_linalg_tests():
    tests = []
    # ... existing tests ...
    
    # Add new test
    A = np.array([[1, 2], [3, 4]])
    result = some_scipy_function(A)
    tests.append({
        'name': 'my_new_test',
        'operation': 'my_operation',
        'inputs': {'A': A.tolist()},
        'expected': result.tolist()
    })
    
    return tests
```

Then add corresponding test case in `tests/test_with_python_data.js`.

## Test Tolerances

Different operations use different tolerances for numerical comparisons:

| Operation | Tolerance | Reason |
|-----------|-----------|--------|
| Basic ops (dot, norm) | 1e-10 | High precision expected |
| Solve | 1e-9 | Some numerical error acceptable |
| Eigenvalues | 1e-4 | Algorithm differences |
| Eigenvalue equation | 1e-3 | Iterative solver variations |

These tolerances account for:
- Floating-point precision differences between JavaScript and Python
- Algorithm implementation variations
- Different convergence criteria in iterative solvers

## Continuous Integration

Tests are automatically run on:
- Every commit to a pull request
- Every push to main branch

Make sure all tests pass before merging code.

## Debugging Test Failures

### Unit Test Failures

Run a specific test file with verbose output:

```bash
node --test --test-reporter=spec test.js
```

### Python Comparison Failures

1. Check if test data needs regeneration
2. Verify tolerance levels are appropriate
3. Add debug output to see actual vs expected values:
   ```javascript
   console.log('Actual:', actual);
   console.log('Expected:', expected);
   ```

### Eigenvalue Test Issues

Eigenvalue tests can be sensitive because:
- Eigenvectors can differ by sign (-v is valid if v is valid)
- Iterative algorithms may converge to different precision
- Lanczos algorithm is simplified compared to scipy's ARPACK

If eigenvalue tests fail:
1. Check if eigenvalues are close (order matters)
2. Verify eigenvector equation A*v = λ*v holds
3. Consider increasing tolerance if numerical differences are small
